行為型GoF

Command

把「一個操作」包成物件，讓它可以被儲存、排隊、還原。

問題情境

你在做一個繪圖板。使用者新增圖形、移動、改顏色，然後要求：我要能 undo。 而且不只一步，要能一路退回去，退錯了還要能 redo。

不用 pattern 會怎樣

最直覺的做法是每次動作前把整份狀態存一份快照：

const snapshots: Drawing[] = [];

function addShape(shape: Shape) {
  snapshots.push(structuredClone(drawing)); // 存整份
  drawing.add(shape);
}

function undo() {
  const previous = snapshots.pop();
  if (previous) drawing = previous;
}

這在圖形只有五個時完全能動。問題在後面：

  • 圖形變成幾千個時，每次移動一格就複製整份狀態，記憶體與延遲都撐不住
  • 每個操作的 undo 邏輯散在各個函式裡，沒有統一介面——想加「把最近 5 步存成巨集」就得整個重寫
  • 快照無法描述「發生了什麼」。UI 想顯示「復原：移動 #3」時，你手上只有一坨舊狀態

用 Command 之後

每個操作變成一個物件，自己知道怎麼做、也自己記住怎麼還原：

interface Command {
  readonly label: string;
  execute(): void;
  undo(): void;
}

class MoveShape implements Command {
  readonly label: string;
  private previous: { x: number; y: number } | null = null;

  constructor(
    private readonly drawing: Drawing,
    private readonly id: string,
    private readonly to: { x: number; y: number },
  ) {
    this.label = `移動 ${id}`;
  }

  execute(): void {
    const shape = this.drawing.get(this.id);
    this.previous = { x: shape.x, y: shape.y }; // 只記兩個數字，不是整份狀態
    shape.x = this.to.x;
    shape.y = this.to.y;
  }

  undo(): void {
    if (!this.previous) throw new Error('undo 在 execute 之前被呼叫');
    const shape = this.drawing.get(this.id);
    shape.x = this.previous.x;
    shape.y = this.previous.y;
  }
}

歷史紀錄退化成兩個堆疊，而且它完全不需要知道每個操作在做什麼：

class History {
  private readonly done: Command[] = [];
  private readonly undone: Command[] = [];

  run(command: Command): void {
    command.execute();
    this.done.push(command);
    this.undone.length = 0; // 做了新動作，原本的「未來」就不存在了
  }

  undo(): Command | undefined {
    const command = this.done.pop();
    if (!command) return undefined;
    command.undo();
    this.undone.push(command);
    return command;
  }
}

最容易寫錯的一行：this.undone.length = 0。 少了它，使用者「undo 兩步 → 做新動作 → redo」時會重演一個已經不存在的分支，狀態直接壞掉。 這條有對應的測試 做了新動作之後，原本的 redo 分支被丟棄。

另一個坑：previous 要在 execute 時捕捉，不是 constructor

如果在 constructor 就記下舊座標，同一個 command 被 redo 時會還原到一個過期的位置—— 因為中間可能已經有別的操作動過它了。這也有測試蓋住。

實際跑跑看

點畫布新增圖形，點圖形選取它，然後試著操作幾步再一路復原。支援 Ctrl+Z / Ctrl+Y。

操作軌跡

    什麼時候不要用

    • 狀態很小而且操作很少——三個欄位的表單要 undo，存整份快照就好。 Command 會讓你為了一個 undo 鍵多寫五個 class。
    • 操作本質不可逆——寄出 email、扣款、刪除遠端檔案。 硬要塞 undo() 只會生出一個騙人的介面。這種情境要的是「補償交易」，不是 Command。
    • 只需要單層 undo——存一個 lastValue 變數就結束了。
    • TypeScript 提醒：如果你的 command 沒有 undo、也不需要被儲存或排隊， 那它其實只是個函式。() => void 就夠了，不用開 class。 Command 的價值來自可還原與可保存，不是「把函式包成物件」本身。

    這個 pattern 的真實用途

    • 編輯器的 undo/redo（VSCode、Figma、Photoshop）
    • 任務佇列：command 可以被序列化後丟進 queue 延後執行
    • 巨集／批次：把數個 command 組成一個複合 command
    • 資料庫的 transaction log 與 event sourcing 是同一個想法的放大版

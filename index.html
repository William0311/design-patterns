設計模式實踐

GoF 23 個設計模式的 TypeScript 實作。每個 pattern 一頁：先講不用它會痛在哪， 再看用了之後，最後一定會寫什麼時候不要用。所有實作都有單元測試。

寫在前面。這 23 個模式出自 1994 年的書，當時的主要語言是 C++ 與 Smalltalk。 在 TypeScript 裡，其中好幾個已經是語言內建功能或反模式。 這個站不會假裝 23 個都同等重要——用不到的會直說用不到，並解釋為什麼在現代語言裡消失了。

行為型 11

  • Command ✅ 把操作包成物件 → undo/redo、佇列、巨集。含可互動的繪圖板 demo。
  • Observer 狀態變動通知多方。理解它就理解了整個前端響應式系統的底層。
  • State 用物件取代到處散落的 if (status === ...)。實務上非常常用。
  • Strategy 演算法可替換。在 TS 裡多半退化成「傳一個函式」——會解釋何時仍值得開 class。
  • Chain of Responsibility 請求沿著鏈傳遞。middleware 就是它。
  • Template Method 骨架固定、細節交給子類。繼承的代表作，也是最容易被組合取代的一個。
  • Mediator 多對多溝通收斂成星狀。用過頭會生出上帝物件。
  • Memento 狀態快照。會直接跟 Command 對照：什麼情況下快照反而比較好。
  • Visitor 對物件結構加新操作而不改結構。TS 的 discriminated union + switch 通常更好。
  • Iterator ⚠ 語言內建。TS 有 Symbol.iterator 與 generator，寫這個 class 沒有意義——會示範內建做法。
  • Interpreter ⚠ 十年寫不到一次。會做一個極小的運算式求值器帶過。

結構型 7

  • Adapter 介面不合就包一層。接第三方 API 時天天用到。
  • Decorator 不動原物件加功能。注意跟 TS 的 decorator 語法是兩回事。
  • Facade 把一坨複雜子系統收成一個好用介面。最沒有爭議、最常無意識使用的一個。
  • Proxy 代理存取：延遲載入、快取、權限。JS 有原生 Proxy 可以對照。
  • Composite 樹狀結構中「單一」與「群組」同介面。UI 元件樹的本質。
  • Bridge 抽象與實作各自獨立變化。最常被跟 Strategy 搞混，會並排比較。
  • Flyweight ⚠ 共用大量細小物件省記憶體。現代場景稀少，但講清楚它解決的是什麼問題。

創建型 5

  • Builder 一步步組出複雜物件。TS 有物件字面量與具名參數，會比較兩者取捨。
  • Factory Method 由子類決定生出哪一種。
  • Abstract Factory 生出一整組相關物件。跟 Factory Method 的差別是常見面試題。
  • Prototype 用複製取代 new。JS 的原型鏈與 structuredClone 讓它幾乎不用手寫。
  • Singleton ⚠ 在 ES module 裡天然成立，而且多數情況該避免——會解釋它為何被歸為反模式。
